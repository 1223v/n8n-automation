04 · 어떻게 검증하나 · n8n 적용 설계

노드가 있는지보다,
연결 양쪽의 데이터가 맞는지 본다

Plan 모드 + n8n-mcpvalidate 통과 → 구조가 맞으면 완료로 보기 쉬움
이 설계샘플 입력으로 앞 노드 출력과 뒤 노드 기대를 비교
앞 노드 출력 · 필드 누락을 넣은 테스트 입력
{
  "status": "success",
  "exitCode": 0,
  "details": {
    "deploymentCompletionUnconfirmedCount": 0
  }
}
뒤 노드 · 실제 정규화 코드의 검사 조건
const countOrNull = (value) =>
  Number.isInteger(value) && value >= 0
    ? value : null;

const approvalDateMissingCount =
  countOrNull(details.approvalDateMissingCount);
필수 필드 누락 → null → 정상 주장 거부 → calendarStatus: failed

모르는 값을 0건으로 채우지 않습니다. “문제 없음”과 “확인 못 함”은 다릅니다.

revfactory/harness · qa-agent-guide.md · 실제 코드: pipeline.json / 01 XML 결과 정규화 · 비교는 같은 n8n-mcp 도구(validate · autofix · test) 기준
